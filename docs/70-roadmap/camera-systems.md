# Camera Systems — Roadmap & Vendor Inventory

**The truth first:** camera integrations are **planned — none are live**. No camera/vision pipeline ships in Meridian today. The research below (consolidated from the former per-vendor briefs in `docs/playbook/_status/cameras/`) maps which brands could feed a future RTSP-based vision-analytics pipeline. "RTSP works" in the Status column means the *hardware* exposes a standards-based stream we could ingest — it does not mean a Meridian integration exists.

Planned support tiers from the briefs: **Officially supported** (standard RTSP/ONVIF, one URL pattern), **Best effort** (works on a subset of SKUs, per-model verification needed), **Not supported** (cloud-only, no local stream — rep script: add a cheap PoE camera, e.g. Reolink or Hikvision, alongside it).

| Vendor | Auth type | Status | Notes |
|---|---|---|---|
| Amcrest | Username + password, Digest | RTSP works (Dahua OEM) | US-facing Dahua rebrand — URL format, ports, ONVIF, and NDAA posture identical to Dahua; one integration covers both. Planned: supported on IP cams/NVRs; best effort on the Smart Home Wi-Fi / doorbell line (per-SKU). |
| Arlo | Arlo account only — no local stream credential | Cloud-only, no RTSP | No RTSP on any model, no ONVIF, no local API; business model is the Arlo Secure subscription. Not supportable. |
| Avigilon (Motorola) | Username + password, Digest (Unity); portal-issued URL creds (Alta) | RTSP works (Unity line) | Enterprise, integrator-sold. Unity H4/H5A/H6A/H6X: port 554, `/defaultPrimary` path, ONVIF S/G — planned supported tier. Alta cloud cameras need an active Alta subscription to expose RTSP — best effort. Credentials usually live with the integrator, not the merchant. |
| Axis | Username + password, Digest | RTSP works | Reference-grade: co-founded ONVIF (Profile S/G/T/M), open VAPIX HTTP API, one URL pattern (`/axis-media/media.amp`) across the lineup. NDAA + TAA compliant — the clean choice for federal/critical-infra customers. Planned supported tier. |
| Bosch | Username + password, Digest | RTSP works | Enterprise (airports, banks, government). ONVIF S/T/G/M conformant, parameterized RTSP URL. Quirks: new firmware defaults to H.265 (force codec param); installs are integrator-owned. Planned supported tier. |
| Camect | Account-based app auth; per-camera creds underneath | Not a camera vendor | AI NVR hub that *ingests* RTSP/ONVIF cameras; no documented rebroadcast API. Rep behavior: identify the cameras behind the Camect and integrate with those directly. |
| Dahua | Username + password, Digest | RTSP works | #2 globally. Port 554 (some HF-series 1554), ONVIF S/T/G. One URL pattern covers Dahua, Amcrest, EmpireTech, and older Lorex — huge SMB slice from one integration. NDAA Section 889 bars federal/contractor use. Planned supported tier. |
| Eufy (Anker) | Username + password set in-app when RTSP toggled, Digest | RTSP on a narrow wired subset | RTSP is a per-camera app toggle on select wired models only; no ONVIF anywhere; battery cams and doorbells (the best-selling SKUs) have no RTSP at all. Best effort, verify per-SKU. |
| Hikvision | Username + password, Digest; separate ONVIF user required | RTSP works | World's largest IP camera maker; predictable URL scheme; Hikvision silicon underlies many other badges. NDAA Section 889 federal caveat (rare for SMB). Planned supported tier. |
| Lorex (Skywatch) | Username + password, Digest | RTSP on N-series NVRs + wired/PoE cams | Dahua-derived firmware kept after the 2023 Skywatch sale — Dahua-format URLs work. W-series standalone Wi-Fi and Smart-Hub battery cams are cloud-only (not supported). Mixed pre/post-2023 hardware means model checks. |
| Google Nest | OAuth 2.0 + Google Device Access project ($5 fee) + per-merchant consent | Cloud-only (no local RTSP) | SDM API grants RTSP only for legacy devices with 5-minute stream lifetimes; newer models are WebRTC-only. Integration cost high, coverage partial. Not supported. |
| Reolink | Username + password, Digest (create non-admin user) | RTSP works on PoE / wired | RTSP on by default, well-documented URLs, $50–150 PoE hardware — this is the recommended "add a cheap camera" brand. Standalone battery (Argus) line has no RTSP unless paired with a Home Hub. Planned supported tier (wired). |
| Ring (Amazon) | Ring account only — no per-camera credential | Cloud-only, no RTSP | No model has ever shipped RTSP or ONVIF; closed Amazon protocol tied to the Ring Protect subscription. Not supportable. |
| Swann | Username + password (Digest; Basic on older Hikvision-OEM SKUs) | RTSP on wired DVR/NVR — brand-specific URL formats | Multiple OEMs across model years (Raysharp now, Hikvision/Dahua before) — no single URL pattern; always ask "what model?" first. Wi-Fi/battery cams on the SwannSecurity/Tracker apps are cloud-only. Best effort. |
| Ubiquiti UniFi Protect | Token-in-URL — the random stream ID *is* the auth; regenerate to revoke | RTSPS (TLS) on port 7441 | Not plain RTSP; must be enabled per-camera, per-quality-tier; no ONVIF. For remote/multi-site, the official Protect HTTP API (Protect 5.3+) beats exposing 7441. Supported locally / best effort remote. |
| Verkada | Username + password set in Command portal, Digest | RTSP works — LAN-only, opt-in per camera | Standards-based RTSP on every current model (unusual for cloud-native), but RFC-1918 LAN-only: collector must sit on the merchant network or use site-to-site VPN. No ONVIF; CR63-E has no RTSP; some models lack RTSP audio. Supported with caveats. |
| Wyze | Username + password set at firmware-flash time | RTSP only via beta firmware flash | Requires a manual flash of a frozen-beta RTSP firmware on a shrinking model list (no v4/OG/v3 Pro/battery) — a support nightmare for non-technical merchants. Not supported. |
