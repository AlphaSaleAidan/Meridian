## TL;DR — the things that bite

1. **Supabase preview == prod.** No branching enabled on the live project. Every migration applies to production. `git push` to a "preview" branch does NOT spin up a preview database. Apply via dashboard SQL editor with rollback in hand.
2. **Mgmt API SQL endpoint silently rejects writes via Cloudflare WAF.** `POST /v1/projects/.../database/query` works for read-only `SELECT` against the `public` schema but returns `error code 1010` on `DELETE`/`UPDATE`/`DROP`. Use the dashboard SQL editor for any DDL/DML.
3. **`auth.users` is not queryable** via the Mgmt API SQL endpoint (returns 403 — the auth schema is restricted). Use `GET /auth/v1/admin/users/<id>` (with service_role) to inspect specific users; there is no public API to list all users by email.
4. **`is_admin()` (SQL) ≠ `ADMIN_EMAILS` (Python).** Both are "the admin list" but they diverge by 3 humans right now (see "Admin source of truth" below).
5. **`playbook.json` (948KB) is generated, gitignored, and required at build time.** Re-generated by `scripts/build-playbook-data.mjs` via `predev`/`prebuild` hooks. Don't commit it. Don't be surprised when it's missing in a worktree until you run `npm run dev` or the script directly.
6. **`frontend/src/lib/format.ts` sniffs `window.location.pathname`** to pick CAD vs USD. A non-portal customer page that handles money will silently default to USD if the URL doesn't start with `/canada`. Use the explicit `formatCad` / `formatCadMo` helpers when the value is known-CAD.

From `supabase/migrations/20260429_003_onboarding_admin.sql:36-40`:

create or replace function is_admin()
returns boolean as $$
  select exists (select 1 from admin_users where user_id = auth.uid());

## Known footguns discovered today (2026-06-03)

These are not in this doc as "things to fix"; they're flagged so future sessions don't waste hours rediscovering them.

### preview == prod for the database

Already covered above. **Re-emphasized because it's load-bearing.** Treat every migration as a prod write. Rollback SQL is the only safety net.

### Supabase Management API SQL endpoint silently WAF-blocks writes

`POST https://api.supabase.com/v1/projects/<ref>/database/query` with `{"query": "..."}` works for `SELECT` against the `public` schema. It returns `403 / error code 1010` (Cloudflare browser-signature block) on `DELETE` / `UPDATE` / `DROP POLICY` / etc. It also returns `403` on `SELECT FROM auth.users` (auth schema is restricted regardless of statement type).

Use cases:
- ✅ Read-only schema introspection (`SELECT * FROM pg_policies WHERE schemaname = 'public' ...`)
- ✅ Read-only data queries against `public` tables
- ❌ Any DDL/DML — fails silently with WAF
- ❌ Anything against `auth.*` — 403

For DDL/DML: use the Supabase dashboard SQL editor (manual, browser). For auth-schema reads: use the auth admin API (`GET /auth/v1/admin/users/<id>` with service_role).

### `playbook.json` is generated, not committed

`frontend/src/data/playbook.json` (~948KB) is `git check-ignore`'d via `frontend/.gitignore:9` with the comment `# Generated by scripts/build-playbook-data.mjs (rebuilt via predev/prebuild)`. The build script reads 217 markdown source files from `docs/playbook/` and bundles them into a single JSON.

`frontend/package.json` wires it to auto-run:

```json
"predev":   "node ../scripts/build-playbook-data.mjs",
"prebuild": "node ../scripts/build-playbook-data.mjs"
```

**Verify before deploy:** the Vercel/CI build command MUST be `npm run build` (not bare `vite build`), or the prebuild hook does not fire and the build will fail because `PlaybookViewer.tsx` imports `@/data/playbook.json`. Tracked separately as a sanity-check task in the overnight report.

In a fresh worktree, run `node scripts/build-playbook-data.mjs` manually before any `tsc --noEmit` or `vite build`. The `tsc` pre-commit hook fails otherwise.

### `format.ts` pathname-based USD fallback

`frontend/src/lib/format.ts:6-11`:

```typescript
function getLocaleConfig(): { locale: string; currency: string } {
  if (typeof window !== 'undefined' && window.location.pathname.startsWith('/canada')) {
    return { locale: 'en-CA', currency: 'CAD' }
  }
  return { locale: 'en-US', currency: 'USD' }
}
```

`formatCents`, `formatCentsCompact`, `formatNumber`, `formatDate`, `formatDateTime`, `formatChartTick`, `formatChartDate` all call `getLocaleConfig()`. **A non-`/canada/*` URL that displays CAD money will silently render it as USD.**

The fix (already in code as of PR #32): explicit `formatCad` / `formatCadMo` helpers that prefix `CA$` regardless of pathname. Use them for known-CAD values; reserve the pathname-aware helpers for values that genuinely depend on the URL's portal context.

### `Mgmt API PAT` lives in a different place than project keys

The Supabase Management API personal access token (`sbp_...`) is at Account → Access Tokens, NOT Project Settings → API. A "rotate all project keys" sweep misses the PAT unless it's explicitly on the list. Tracked as task #24.
