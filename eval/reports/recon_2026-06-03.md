## Implied churn label — base rate by (lookback, horizon, min visits)

Label: a customer is **churned at cutoff C** iff
  - they had a transaction in `[C - lookback, C]`, AND
  - they had >= `min_visits` lifetime transactions, AND
  - they had **no** transaction in `(C, C + horizon]`.

`C` = `MAX(transaction_at) - horizon` (the latest cutoff that
still has a full horizon of post-cutoff data).

## Verdict — is a defensible real-data churn eval feasible?

**NOT FEASIBLE** on the production Meridian DB at this time.

- Transactions table holds 3 rows. Largest single customer-identity column populates 0 rows. Maximum eligible cohort across all parameterisations: 0.
- The table census above shows the broader picture: every customer-history table (`customer_journeys`, `customer_sessions`, `anonymous_customer_profiles`, `chat_conversations`, `phone_orders`, ...) is empty. The production Meridian Postgres has not yet accumulated the purchase history a real-data churn eval would consume.

### Minimum-viable alternatives

1. **Wait for organic data.** As more POS connections onboard and customer-link columns get populated, re-run this script. Re-evaluate when `n_eligible ≥ 1,000` on at least one parameterisation.
2. **Pull from Latham CRM** (read-only export to the VPS) and run the harness against Latham's real customer-purchase history. Most direct path; preserves the "real data" discipline that motivated this whole project.
3. **Pull from the Square integration directly** via the Customers + Payments APIs (`SQUARE_ACCESS_TOKEN` is on this box). Mirrors what Meridian will eventually have in-table, with the trade-off that the data covers only the Square-connected location(s).
4. **Public retail-churn dataset** (UCI Online Retail, Kaggle Telco Churn). Real but off-domain — useful for proving the harness end-to-end without committing to a model choice. Lowest transfer value to production Meridian.

Phase 2 (`eval/harness.py`) and Phase 3 (survival model) should NOT proceed against this DB. Pick an alternative or defer; either is honest.
